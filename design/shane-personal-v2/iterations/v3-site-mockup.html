The Build Field Guide

Eleven gates, each carrying a decision I actually made and at least one I got wrong. The loop does the work between the gates; you work the gates. Four of the eleven are shown here.

Loop & Gate · Build Kit · rev 0.2.0

Run it by hand first

Concierge the whole workflow yourself before you automate a step of it. You're not testing whether it can be automated — you're finding out which part was actually the work.

1

Specify the failure, not the feature

"If this breaks next month, what turns red?" A spec that can't name its own alarm hasn't specified anything — it's described a demo, and demos don't survive contact with next month.

2

Let rigor scale to blast radius

Two gates for a copy change, all ten for anything touching billing or customer data. Process weight is a function of what you can't take back, not of how important the work feels.

3

Kill the framing before the tech

The tell is "you can only charge for it once." When a product only works as a one-time discovery, the engine is usually fine — it's pointed at the wrong job.

The governing rule · this page is the spec, not a site page

Architecture is a function of content type.

One visual system — Drafting palette, dimensioned figures, 45° hatch, numbered callouts. Five architectures, each earned by a kind of content. The point isn't variety; it's that a reader who lands on a sequence gets a sequence, and a reader who lands on a reference page gets a title block telling them when it was last true.

Figure taxonomy

Five figure types. A figure is additive or it doesn't ship — these are the only shapes, and each states what it requires before it may be used.

Dimensioned diagramA claim about proportion or where a line sitsTwo regions and a measured split you can defend

Record chartA claim about your own history or dataA file it reconciles to, named in the caption
DetailClarifying one step of an assemblyA step that's actually unclear without it
Footed tableAnything with numbers, including pricingFigures that add up, shown adding up

Two corrections this pass

  1. 01
    Lists are ordered by date descending, never grouped by category. Category is metadata on the row and a filter above the list — grouping breaks reverse chronology, which is the only ordering a reader can predict. Numbering runs 001 = newest, matching the live folio.
  2. 02
    The practice is demoted, on purpose. It's not in the primary nav — footer only — and on the home page it's one muted line with no heading and no figure. An earlier draft of this mockup gave it a nav slot and a featured band, which contradicts how the live site actually weights it.

The rules that keep it honest

  1. 01
    No figure without a caption naming its source. A drawing that can't say where its numbers came from is decoration wearing a lab coat.
  2. 02
    If the page is no worse without the figure, cut the figure. Additive means additive. This is the rule that stops the system becoming a house style you decorate with.
  3. 03
    Architecture follows content, never mood. If a page doesn't match a row in the mapping table, the answer is a new row with a stated reason — not an improvised layout.
  4. 04
    Annotation red marks only what the drawing calls out. Dimensions, callouts, corrections, the one thing that turned red. It never styles a heading.
  5. 05
    Every rule is 1px. Bigger divisions are whitespace, not heavier lines. Inherited from v2 and unchanged.
  6. 06
    Revision and date are content. Any page carrying a title block states when it was last true. A stale sheet that admits it beats a fresh-looking one that doesn't.

What changes from v2

  1. +
    Annotation red #c0392b joins the palette with one strict role. Cream, ink, and olive are unchanged — olive keeps links and states.
  2. +
    Five named architectures and the mapping table above. v2 had one page shape and a component list; this has five shapes and a rule for choosing.
  3. +
    A figure taxonomy with entry requirements, plus the title block as a real primitive.
  4. −
    The generic footer row is gone from any page carrying a title block — the block is the footer.
